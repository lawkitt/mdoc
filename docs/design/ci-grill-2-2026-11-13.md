## Round 1

1. **#836's drop is fixed in #836.** The wait after tapping Original goes
   to 15 s (commit fde08614) and the PR is queued again; a new push is not
   ADR 0112's one re-queue.
2. **ADR 0112's unrelated-failure rule stays mechanical.** No clause for
   "the recording shows the app got there": a judgement from a video is
   one the hub would make inconsistently. Round 1's item 3 removes the
   cause instead.
3. **UI tests share one timeout for waits on a state to appear** (for
   example `MdocUITest.timeout = 15`), replacing the 5 s waits in one PR.
   Such a wait returns as soon as its condition holds, so passing tests
   are no slower. Waits for something to go away (`waitForNonExistence`,
   which always spend their time when the check is negative) stay
   separate.
4. **This grill's goal: a lower queue median, and fewer drops and
   flakes.** The levers are the macOS runner-minutes a core change spends
   (round 2).
5. **ROADMAP CI speed item 22 closes as not needed**: since item 16 the
   PC's Windows job takes 6–7 minutes.
6. **The iOS core cache key goes to v2** (#839, queued 11-13).

## Round 2

7. **Targets by what a commit runs.** A core change's queue time median
   20 minutes or less; a desktop-only change's 15 or less; ADR 0112's
   overall median of 25 stays as a floor. One overall median hides the
   slow path: a day of docs PRs passes it.
8. **Detection runs only when its inputs change**: core, recognition,
   `resources/` and the crates the gate builds (`mdoc-detect` and its
   `mdoc-*` dependencies). App-only files (`src/`, `vendor/`, `build/`,
   `tests/` outside the recognition fixtures) leave detection's area, so
   a desktop-only change runs `ci/macos` and not six detection shards.
9. **The UI shards split by measured time**: a committed table of test
   class times from recent xcresults, which the shard script reads and the
   nightly refreshes. No build-once hand-off: it saves about 3
   runner-minutes and puts a serial build on the critical path.
10. **The `mdoc-detect` rule pack is built once per test process** (a
    lazily built shared pack), not in nearly every unit test; the pack is
    immutable once built.
11. **A failed iOS job names its failing tests**: `ci-ios.yml` reads the
    xcresult and puts them in the job's error and summary, as the PC's
    status does, so `ci-stats.sh` and the hub apply ADR 0112's "same test
    elsewhere" rule to hosted iOS failures.
12. **Hosted iOS UI tests retry once** (`-retry-tests-on-failure
    -test-iterations 2`). A pass on the retry keeps the job green, is
    reported by name, and counts as an unrelated failure toward ADR 0112's
    quarantine after two. Unit, Rust, Android and script tests still never
    retry.
13. **UI tests launch from a prebuilt library**, a fixture copied into the
    app's container instead of an import at each launch: measured first on
    the class with the most launches, then every class if it saves at least
    5 s a launch.

## Facts found before round 3

- **Where detection can run.** The gate needs mdoc's pinned ONNX Runtime,
  which mdoc supports only on macOS arm64 and Windows x86_64
  (`mdoc_import::ocr::SUPPORTED`); Linux would need a new pinned runtime in
  product code. Hosted `windows-latest` is free for this public repo and
  draws on the 20-job pool shared with Linux, not the 5 macOS slots.
- **Snapshots are platform-bound.** `Snapshot::stale` allows a score
  difference of 1e-4, and `recognize.rs` names the Mac as the reference
  platform for `--refresh-snapshots`. A gate on Windows means recording the
  256 `*.model.json` snapshots there once and making Windows the reference;
  Mac agents would then take refreshed snapshots from CI's
  `detection-snapshots-<k>` artifacts (`just snapshots-fetch`, which
  exists). Recognition work already runs from a Windows hub (ADR 0108). How
  many snapshots change, and how fast the FP16 model runs on a 4-vCPU x86
  runner, are not measured.
- **Narrowing detection's core trigger saves little.** Of 186 commits on
  `main` since 10-30 that touched the core area, 126 touched a crate the
  gate builds (`mdoc-detect`, `-pii`, `-import`, `-history`, `-spell`,
  `-store`), 40 only shared build files (`Cargo.lock`, `justfile`, the
  toolchain, the shared scripts) and 20 only other crates.

## Round 3

14. **Detection moves to hosted `windows-latest`, and Windows becomes its
    reference platform**, after one trial dispatch on a branch that
    measures the time per fixture and how many snapshots change, and sets
    the shard count. The snapshots are recorded there once. If the FP16
    model cannot fit its 5-minute budget even in 12 shards, detection stays
    on macOS and this question comes back.
15. **Detection's core trigger stays as it is.** Narrowing it to the
    crates the gate builds would skip about one core commit in nine, and
    on the Windows pool a skip frees no macOS slot.
16. **The iOS UI target is per shard**: the slower UI shard's median 15
    minutes or less, replacing ADR 0112's `ci/ios (ui)` 20.
17. **`ci-stats.sh` classifies queue commits** (core, desktop-only,
    iOS-only, other) and reports rounds 2 and 3's targets; the nightly's
    issue after 3 red nights judges only data from after each change.
    Targets and check land in one PR.
18. **A new ADR 0113 amends ADR 0112**, with ROADMAP "CI speed" items from
    23, one per decision.
19. **A fresh hub session builds it**, from the ADR and the ROADMAP items,
    lanes on wsl and windows by the fleet skill. Order: failing iOS test
    names and detection's area first, then the shared UI timeout, the rule
    pack, the shard table, the UI retry, the launch trial, and the
    detection trial last.
