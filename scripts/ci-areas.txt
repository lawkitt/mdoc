# The area table (ADR 0091): which CI jobs a change runs. One line per
# glob: the areas it belongs to (comma-separated), then a GitHub filter glob
# (`**` crosses directories, `*` and `?` do not). A file takes the areas of
# the first line that matches it; a file no line matches is desktop.
#
#   none     no job runs: docs and files no build reads. These lines are
#            ci.yml's paths-ignore list, word for word (scripts/test-local-ci.sh
#            fails when they disagree), and come first, so a README under
#            apps/ or crates/ is still docs. Only exceptions precede them:
#            Markdown under tests/fixtures/ that a test reads (the recognition
#            fixtures, ADR 0093: recognition, below). The merge queue runs
#            them as their area; ci.yml's push filter still skips them
#            (paths-ignore has no exceptions).
#   ios      the iOS job (ci/ios): apps/ios/ and the iOS scripts.
#   android  the Android job (ci/android): apps/android/ and the Android
#            scripts.
#   recognition  the recognition fixtures (ADR 0093): only the detection
#            gate (ci/detection) runs; the desktop and mobile jobs are not
#            affected. The full desktop jobs run too when the change is
#            also desktop.
#   core     every area: the Rust core and what every job builds with (the
#            toolchain, the workspace manifest and lock, the justfile, and
#            the shared scripts lib.sh, tools.env and setup.sh with what it
#            runs). The table itself is core.
#   desktop  ci/macos and ci/windows (lint, test, and on macOS the mobile
#            cargo check), the detection gate, and hosted clippy and test: src/, tests/,
#            vendor/, build/, resources/, .github/ and every script not
#            listed here (the desktop scripts: release, packaging, smoke
#            tests and the suites of those).
#   ci       the CI machinery (ADR 0100): the merge gate, the queue runner,
#            the CI scripts, the workflows that build and test nothing
#            themselves, and their suites. On a queue commit only ci/scripts
#            runs (the script suites on Linux and under macOS /bin/bash 3.2)
#            beside lint (ubuntu); the desktop suite does not. A workflow
#            that builds or tests the app takes the area of what it runs:
#            ci-desktop.yml, ci-detection.yml, queue.yml (which starts
#            them) and release.yml are desktop, ci-ios.yml ios,
#            ci-android.yml (merge-gate's Android fallback) android.
#
# A script two areas run belongs to both: mobile-check.sh is the Mac's
# desktop cargo check (`--ffi`) and the iOS job; install-android-ndk.sh
# serves that cargo check and the Android job.
#
# scripts/ci-areas.sh prints the areas a change touches (queue.yml's and
# ci.yml's areas jobs run it); merge-gate.sh and the PC's queue-runner.sh
# read a queue commit's own copy; local-ci.sh, mobile-check.sh and
# android-check.sh read it too.
